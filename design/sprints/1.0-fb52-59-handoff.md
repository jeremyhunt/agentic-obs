## How to work on this

**Invoke the `superpowers:test-driven-development` skill before writing
implementation code.** Not just at the start of a session — at the point of
implementing. FB-52 through FB-57 were written fix-first, tests-after, and
FB-59's audit found five untested paths plus one real defect as a direct result
(see below). FB-58 onward was done RED-first.

The cycle that has been working here:

1. **RED** — write the test, run it, confirm it fails *for the reason you expect*.
   A compile error is not a failure; make it compile, then watch it fail on the
   assertion.
2. **GREEN** — the minimum that passes.
3. **REFACTOR** — deduplicate under a green test.
4. **Mutation-check** — break the production code and confirm the test fails.
   **Mutate the layer the test actually covers.** A mutation in the wrong layer
   proves nothing and looks like success: breaking the goobs conversion left an
   MCP handler test green, because `MockOBSClient` replaces that layer entirely.

For tests touching real resources, see the existing rule about hermeticity being
a *precondition* of the RED run, not a cleanup step.

**Verification is per-increment, not per-session:**

```
go build ./... && go vet ./... && go test ./...
./scripts/verify-docs.sh && ./scripts/verify-skills.sh
go vet -tags obslive ./internal/obs/...          # the live suite must still compile
```

`go test` caches aggressively. **Run `go clean -testcache` before trusting a
green result** — a stale pass masked a real failure at least once here.

## Things that cost real time to learn

**goobs marshals with no `omitempty`.** A field you never set is *transmitted as
zero*, not omitted, and obs-websocket acts on it. This is one mechanism behind
three separate findings:

- a field missing from `obs.SceneItemTransform` was sent as `0` and applied
  (FB-54, the alignment bug);
- an unset `BoundsType` is sent as `""` and **rejected** — `RequestFieldEmpty`
  (403);
- unset `BoundsWidth`/`BoundsHeight` are sent as `0` and **rejected** —
  `RequestFieldOutOfRange` (402), enforced even for `OBS_BOUNDS_NONE`.

The last two are only survivable today because every transform tool is
read-modify-write and so carries real values back. **Anything constructing a
transform from scratch must set a bounds type and non-zero bounds dimensions.**
`apply_scene_spec` will do exactly that.

**OBS refcounts sources, so a scene item is not a handle you can freely drop.**
Removing an input's *only* scene item frees the input: `obs_sceneitem_remove`
releases the last reference and the source is destroyed. "Remove the placement,
keep the source" only holds while another placement exists — which is the case
`apply_scene_spec` actually cares about, since `OVERLAY_NowPlaying` lives in two
scenes. The contract states it that way (FB-60). The complementary case is
deliberately not asserted: destruction is deferred to the graphics thread, so
reading straight after a removal races.

**`internal/storage/db.go` `migrate()` forbids `ALTER TABLE`.** It re-executes
every statement on every boot and works only because all of them are
`CREATE … IF NOT EXISTS`. Schema changes must be new tables.

**`MockOBSClient` is not a wrapper, it is a replacement.** Nothing below it
(`internal/obs`, goobs, the wire) is exercised by any test that uses it. It also
keeps scene items, transforms and lock states in three unrelated maps, so two of
its methods can disagree about the same item. `internal/obs/obstest.Fake` is the
replacement being grown; it keeps one world.

**`-race` cannot run locally** — it needs cgo, which ADR-001 deliberately keeps
off. CI runs it on Linux.

**The live contract suite cannot gate CI** (no OBS on a runner). It is a local
and pre-release gate:

```
OBS_LIVE_TEST=1 OBS_HOST=localhost OBS_PORT=4455 OBS_PASSWORD=… make test-live
```

It creates and removes a scratch scene **per row** in the **active** scene
collection — thirteen of them as of FB-60. The owner approved this for the `PC`
collection. **Check the active collection before running it**
(`%APPDATA%\obs-studio\global.ini`, key `SceneCollection`), and confirm nothing
is left behind afterwards: no scene or input named `agentic-obs-contract-*`, and
the scene count back at its starting value. Cleanup held through the FB-60 run,
but verify rather than assume. Note the collection is the thing that matters
here; the profile holds encoder and output settings the contract never touches.

## What is next

**Still open:** whether this work is proposed to `origin` at all, and as a PR or
a direct push. It is backed up on `fork` either way, so this is no longer
urgent — but the longer `origin` sits 31+ commits behind, the more a later PR
has to carry in one review.

**Remaining from increment 0c:**

- Grow the contract suite further. Thirteen rows now cover scene-item transforms,
  visibility, the input lifecycle and filters, against 66 request methods. The
  method is proven and the rest is mechanical; pick the next rows by where a
  wrong assumption would be expensive, not by what is uncovered. Candidates:
  scene-item ordering (`SetSceneItemIndex` — relative rank is what a spec diffs
  on), audio (mute, volume in dB vs multiplier), `GetSourceSettings` round-trip
  with `overlay` on inputs as well as filters.
- ~~Role interfaces~~ — done in FB-61. What is left of plan 0c(v) is the typed
  `Event{Type, At, Payload}` + `EventSink`, with `EventCallback` kept as a
  deprecated adapter. The event side is still a 17-method callback interface
  that every implementer must satisfy whole.
- **The plan's 0c(iv) is wrong about filter events and should not be
  implemented as written.** It calls for mapping them to `obs://scene/{name}`
  updates, but that resource publishes visibility and transform and *no filter
  state*, so a filter change cannot alter what a subscriber reads back —
  the notification would be noise. It becomes correct only if the resource
  carries filters, which plan §4.7 rejected on round-trip cost. FB-63 pins the
  rule with a test in both directions; revisit only alongside that resource.
  `VendorEvent` is still 2a, and still untranslated.
- Migrate `MockOBSClient` onto `obstest.Fake` so there is one double, not two.
  FB-60 made this more urgent: the fake now models scenes, inputs and filters as
  one world with strict lookups, so it is close to a drop-in replacement, and
  every day both exist is a day they can disagree. `SceneSource.Visible` is the
  cautionary tale — *both* doubles populated it while the real client never did,
  so every test agreed with a client that was wrong.

**Then Phase 1** — the gateway tools that unblock `TGV-SongifyWidget`:
`set_source_settings`, `press_source_properties_button`, `ensure_input`,
`get_input_default_settings`, `list_input_property_items`, `take_screenshot`.
`obs_wire.py:6-8` documents why it bypasses agentic-obs today.

The full plan, including the research it came from and the alternatives already
rejected, is at
`~/.claude/plans/research-https-github-com-chriscodinglif-distributed-rainbow.md`.
Read §4.7 (proposals reviewed and rejected) before re-proposing anything.
